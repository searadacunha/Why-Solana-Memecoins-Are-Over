# Tracing and storage audit, 4 November 2026

Base: `forensics-v2` at `d4cf1d57e1eef2857be0cdde8b369c561664a89d`.

## Confirmed defects

1. **Distinct transfers were lost from the trace graph.** The graph deduplicated
   by transaction signature, source and destination. Two separate instructions
   between the same addresses therefore collapsed to the first payment. A
   synthetic transaction containing payments of 700 and 500 lamports produced
   a graph containing only 700. The graph now includes the instruction path and
   evidence basis in its deduplication key, matching the store's event identity.
   Reading the transaction from both endpoints still books each movement once.

2. **An interrupted ingest could become permanently incomplete.** Direct calls
   to `store.ingest` inserted the parent transaction before its child rows. If
   a later insert failed, the parent remained and a retry skipped its signature.
   Ingest now owns an atomic database transaction for the batch and rolls it
   back on failure or interruption. The existing `load_store` caller delegates
   its transaction boundary to ingest. A regression test inserts a valid row
   followed by a deliberately invalid row: the whole new batch is rolled back,
   previously committed data remains, and a corrected retry succeeds.

Both regression tests fail against the base implementation and pass after the
corrections. No private wallet, real trading total or fabricated study result
is included in these synthetic fixtures.

## Checks and limits

- CPython 3.12.14; DuckDB 2.0.0; pytest 9.2.0; Ruff 0.17.3; mypy 2.4.1.
- **181 tests pass, 2 skip.** The two skips require the author's private trading
  files and private wallet ledger, which are absent from this checkout.
- Ruff passes on the complete checkout. Strict mypy passes on the changed
  tracer, store and store-loader modules with the repository configuration.
- All 286 Python files present at the branch base parse successfully.
- Existing integrity tests confirm that changes remain inside `forensics_v2/`
  relative to this research branch's established base and README exception.
  This correction itself changes no README.

These checks do not recompute unpublished studies or establish wallet ownership,
intent or insider trading. Existing generated graphs and databases are not
rewritten. A database already affected by a partial historical ingest requires
an explicit integrity assessment and controlled rebuild; the corrected writer
prevents new partial batches and cannot infer which old child rows are missing.
